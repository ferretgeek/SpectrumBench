# 部署指南 / Deployment Guide

## 简体中文

### 安全模型

面板界面会短暂接触 API Key，因此默认只监听回环地址。服务器部署的推荐入口是 SSH 隧道；Docker Compose 也只映射到宿主机 `127.0.0.1`。不要用防火墙放行或反向代理把面板直接暴露到公网。

启动器会打印一个带 `#session=...` 的访问地址。fragment 不会发送给 HTTP 服务，前端只把令牌作为 WebSocket 子协议完成本机会话认证；请通过 SSH 隧道打开完整地址且不要转发。需要跨重启保持固定令牌时可设置至少 32 字符的 `SPECTRUMBENCH_SESSION_TOKEN`，否则每次启动都会生成新值。

### 本地 Python

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
.\.venv\Scripts\python token_stress_test.py
```

Linux / macOS：

```bash
python3 -m venv .venv
./.venv/bin/python -m pip install -r requirements.txt
./.venv/bin/python token_stress_test.py --no-browser
```

运行状态默认写入项目目录；可通过 `SPECTRUMBENCH_DATA_DIR` 指定独立数据目录。状态文件只包含非敏感草稿与脱敏历史。

### Docker Compose

```bash
cp .env.docker.example .env
docker compose up --build -d
docker compose ps
```

健康检查：

```bash
curl --fail http://127.0.0.1:18976/healthz
```

停止与升级：

```bash
docker compose down
git pull --ff-only
docker compose up --build -d
```

数据位于命名卷 `spectrumbench-data`。更新镜像不会删除它；`docker compose down -v` 会删除卷，因此不应在常规升级中使用。

### Linux systemd

以下命令以 Debian/Ubuntu 为例，需要管理员权限：

```bash
sudo useradd --system --home /nonexistent --shell /usr/sbin/nologin spectrumbench
sudo install -d -o spectrumbench -g spectrumbench /opt/spectrumbench /var/lib/spectrumbench
sudo cp -a . /opt/spectrumbench/
sudo python3 -m venv /opt/spectrumbench/.venv
sudo /opt/spectrumbench/.venv/bin/python -m pip install -r /opt/spectrumbench/requirements.txt
sudo chown -R spectrumbench:spectrumbench /opt/spectrumbench /var/lib/spectrumbench
sudo cp deploy/spectrumbench.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now spectrumbench
sudo systemctl status spectrumbench
```

在自己的电脑建立隧道：

```text
ssh -L 18976:127.0.0.1:18976 user@example.com
```

然后访问 `http://127.0.0.1:18976`。如果本机端口冲突，可把第一个 `18976` 改成其他未占用端口。

### 备份与恢复

本地/systemd 只需备份数据目录中的 `stress_state.json`。它不含 Key 或 Base URL，但可能包含样本标签和测量统计，仍应按个人数据保护。恢复时停止服务、替换文件、确认文件所有者后再启动。

### 架构、卸载与排错

浏览器把单次 API Key 和 Base URL 交给同源 Python 服务；服务按锁定场景串行调用 Responses API，再把脱敏测量状态写入 `stress_state.json`。Key 和 Base URL 不持久化。公网访问会扩大凭据暴露面，因此服务器入口仍是回环监听加 SSH 隧道。

- 本地卸载：停止进程、删除虚拟环境/源码；确认不再需要历史后再删除数据目录。
- Docker 卸载：先 `docker compose down`；只有已验证备份且确定不要历史时才使用 `docker compose down -v`。
- systemd 卸载：`systemctl disable --now spectrumbench`，移除单元并 reload，再删除 `/opt/spectrumbench`；`/var/lib/spectrumbench` 单独按备份决定保留或删除。
- `/healthz` 失败：检查进程、回环端口、数据目录权限与只读容器挂载。
- 请求失败：确认端点是允许的 HTTPS 地址、Key 未过期、模型可用且网络能到达 API；不要把 Key 或完整上游响应写进日志。
- 结果被标为不可比较：核对模式版本、推理等级、usage 完整性和质量门禁；不要手工修改状态把降级结论改成正式成绩。

删除历史不可由项目恢复。若 Key 曾进入日志、截图或浏览器扩展，应在提供方撤销，而不是只卸载应用。

## English

### Security model

The dashboard temporarily handles an API key, so the service binds to loopback by default. Use an SSH tunnel on servers. Docker Compose also publishes to host `127.0.0.1` only. Do not expose the panel directly through a public firewall rule or reverse proxy.

The launcher prints an access URL containing `#session=...`. The fragment is never sent in HTTP requests; the UI uses it only as a WebSocket subprotocol credential. Open the complete URL through the SSH tunnel and do not share it. Set a random 32+ character `SPECTRUMBENCH_SESSION_TOKEN` only when a stable token across restarts is required; otherwise each start generates a new one.

### Local Python

```bash
python3 -m venv .venv
./.venv/bin/python -m pip install -r requirements.txt
./.venv/bin/python token_stress_test.py --no-browser
```

State is written to the project directory by default. Set `SPECTRUMBENCH_DATA_DIR` for a separate data directory. Persisted state contains only non-sensitive draft fields and sanitized history.

### Docker Compose

```bash
cp .env.docker.example .env
docker compose up --build -d
curl --fail http://127.0.0.1:18976/healthz
```

Upgrade with `docker compose down`, `git pull --ff-only`, and `docker compose up --build -d`. The named `spectrumbench-data` volume survives image updates. Do not use `docker compose down -v` during a routine upgrade because it deletes the volume.

### systemd and SSH

Install the repository under `/opt/spectrumbench`, create a non-login `spectrumbench` user and `/var/lib/spectrumbench`, install the virtual environment, then copy `deploy/spectrumbench.service` to `/etc/systemd/system/`. Enable it with `systemctl enable --now spectrumbench`.

From your workstation:

```text
ssh -L 18976:127.0.0.1:18976 user@example.com
```

Open `http://127.0.0.1:18976`. If the local port is busy, change only the first port number.

### Backup and restore

Back up `stress_state.json` from the data directory. It contains no key or Base URL, but it can include run labels and measurement statistics, so treat it as personal data. Stop the service before replacing it and restore the expected file owner before restarting.

### Architecture, removal, and troubleshooting

The browser sends a one-run API key and Base URL to the same-origin Python service. The service calls the Responses API serially under locked scenarios and persists only sanitized measurements in `stress_state.json`; it does not persist the key or Base URL. Server use remains loopback plus an SSH tunnel.

- For local removal, stop the process and remove the environment/source; delete the data directory only when history is no longer needed.
- For Docker, run `docker compose down`; use `-v` only after a verified backup and an explicit decision to erase history.
- For systemd, disable/stop the unit, remove and reload it, then remove `/opt/spectrumbench`; retain or erase `/var/lib/spectrumbench` separately.
- A failed `/healthz` points to the process, loopback port, data permissions, or volume mount.
- API failures require checking the allowed HTTPS endpoint, key validity, model availability, and network without logging the key or full upstream response.
- A non-comparable result should stay degraded until the mode version, reasoning level, complete usage, and quality gates agree.

If a key reached logs, screenshots, or an untrusted browser extension, revoke it at the provider; uninstalling the app is not sufficient.
