# 部署指南 / Deployment Guide

## 简体中文

### 安全模型

SpectrumBench 的界面会短暂接触 API Key，因此默认只监听回环地址。服务器部署的推荐入口是 SSH 隧道；Docker Compose 也只映射到宿主机 `127.0.0.1`。不要用防火墙放行或反向代理把面板直接暴露到公网。

### 本地 Python

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
.\.venv\Scripts\python token_stress_test.py
```

Linux / macOS：

```bash
python3 -m venv .venv
./.venv/bin/python -m pip install -r requirements.txt
./.venv/bin/python token_stress_test.py --no-browser
```

运行状态默认写入项目目录；可通过 `SPECTRUMBENCH_DATA_DIR` 指定独立数据目录。状态文件只包含非敏感草稿与脱敏历史。

### Docker Compose

```bash
cp .env.docker.example .env
docker compose up --build -d
docker compose ps
```

健康检查：

```bash
curl --fail http://127.0.0.1:18976/healthz
```

停止与升级：

```bash
docker compose down
git pull --ff-only
docker compose up --build -d
```

数据位于命名卷 `spectrumbench-data`。更新镜像不会删除它；`docker compose down -v` 会删除卷，因此不应在常规升级中使用。

### Linux systemd

以下命令以 Debian/Ubuntu 为例，需要管理员权限：

```bash
sudo useradd --system --home /nonexistent --shell /usr/sbin/nologin spectrumbench
sudo install -d -o spectrumbench -g spectrumbench /opt/spectrumbench /var/lib/spectrumbench
sudo cp -a . /opt/spectrumbench/
sudo python3 -m venv /opt/spectrumbench/.venv
sudo /opt/spectrumbench/.venv/bin/python -m pip install -r /opt/spectrumbench/requirements.txt
sudo chown -R spectrumbench:spectrumbench /opt/spectrumbench /var/lib/spectrumbench
sudo cp deploy/spectrumbench.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now spectrumbench
sudo systemctl status spectrumbench
```

在自己的电脑建立隧道：

```text
ssh -L 18976:127.0.0.1:18976 user@example.com
```

然后访问 `http://127.0.0.1:18976`。如果本机端口冲突，可把第一个 `18976` 改成其他未占用端口。

### 备份与恢复

本地/systemd 只需备份数据目录中的 `stress_state.json`。它不含 Key 或 Base URL，但可能包含样本标签和测量统计，仍应按个人数据保护。恢复时停止服务、替换文件、确认文件所有者后再启动。

## English

### Security model

The dashboard temporarily handles an API key, so SpectrumBench binds to loopback by default. Use an SSH tunnel on servers. Docker Compose also publishes to host `127.0.0.1` only. Do not expose the panel directly through a public firewall rule or reverse proxy.

### Local Python

```bash
python3 -m venv .venv
./.venv/bin/python -m pip install -r requirements.txt
./.venv/bin/python token_stress_test.py --no-browser
```

State is written to the project directory by default. Set `SPECTRUMBENCH_DATA_DIR` for a separate data directory. Persisted state contains only non-sensitive draft fields and sanitized history.

### Docker Compose

```bash
cp .env.docker.example .env
docker compose up --build -d
curl --fail http://127.0.0.1:18976/healthz
```

Upgrade with `docker compose down`, `git pull --ff-only`, and `docker compose up --build -d`. The named `spectrumbench-data` volume survives image updates. Do not use `docker compose down -v` during a routine upgrade because it deletes the volume.

### systemd and SSH

Install the repository under `/opt/spectrumbench`, create a non-login `spectrumbench` user and `/var/lib/spectrumbench`, install the virtual environment, then copy `deploy/spectrumbench.service` to `/etc/systemd/system/`. Enable it with `systemctl enable --now spectrumbench`.

From your workstation:

```text
ssh -L 18976:127.0.0.1:18976 user@example.com
```

Open `http://127.0.0.1:18976`. If the local port is busy, change only the first port number.

### Backup and restore

Back up `stress_state.json` from the data directory. It contains no key or Base URL, but it can include run labels and measurement statistics, so treat it as personal data. Stop the service before replacing it and restore the expected file owner before restarting.
